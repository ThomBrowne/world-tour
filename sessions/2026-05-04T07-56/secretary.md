# 🛠️ GitHub Sync 실패 해결 체크리스트 (CEO 보고용)

**에러 코드:** `fatal: couldn't find remote ref main`
**목표:** 로컬 브랜치와 원격 저장소 간의 참조(Reference) 불일치를 해소하고, 데이터 파이프라인의 신뢰성을 즉시 확보한다.
**적용 원칙:** 문제 해결 과정은 '기술적 수정'이 아닌, **'Who/What/When'이 구조화된 프로세스**를 통해 진행한다.

---

## 🔍 1단계: 원인 진단 (Why) - 문제의 본질 파악

| 원인 분류 | 상세 문제 (What) | 발생 시나리오 (When) | 해결의 핵심 (Why) |
| :--- | :--- | :--- | :--- |
| **1. 참조 불일치** (가장 유력) | 로컬은 `main` 브랜치를 사용하려 하지만, 원격 저장소는 여전히 `master`로 남아있는 경우. | 프로젝트 초기 설정 시 `master`로 시작했으나, 최신 관행을 따라 `main`으로 변경하려 시도할 때. | **로컬과 원격의 메인 브랜치 이름을 일치**시키는 것이 최우선 목표다. |
| **2. 권한 문제** | 사용된 Personal Access Token (PAT) 또는 SSH 키의 쓰기(Write) 권한이 만료/누락된 경우. | 장기간 비활성 상태였거나, 권한 범위(Scope)가 `repo` 쓰기 권한을 포함하지 않을 때. | **인증 정보의 유효성을 재확인**하고 필요한 모든 쓰기 권한을 재발급받아야 한다. |
| **3. 추적 설정 오류** | 로컬 브랜치가 어떤 원격 브랜치를 추적해야 하는지(Upstream) 설정되지 않은 경우. | 새 브랜치를 생성했지만, 원격 저장소에 연결(Push)하는 과정을 명시하지 않았을 때. | **원격 추적 관계를 명시적으로 재설정**하여 동기화 실패를 막아야 한다. |

---

## ⚙️ 2단계: 해결 단계 (How) - 실행 순서 및 담당자 지정

| 순서 (When) | 담당자 (Who) | 작업 목표 (What) | 명령어 및 액션 (How) |
| :---: | :--- | :--- | :--- |
| **Step 1** | 개발자 (Developer) | **현황 진단:** 로컬과 원격의 실제 브랜치 이름 목록을 확인한다. | 1. `git branch` (로컬 브랜치 확인) <br> 2. `git branch -r` (원격 브랜치 목록 확인) <br> **[판단]** 원격의 메인 브랜치가 `master`인지 `main`인지 결정한다. |
| **Step 2** | 개발자 (Developer) | **이름 통일:** 만약 불일치가 발견되면, 로컬 브랜치 이름을 원격과 일치시킨다. (예: 원격이 `master`라면) | `git branch -m main master` <br> *(주의: 이 명령은 로컬 브랜치 이름만 변경하며, 코드는 그대로 유지한다.)* |
| **Step 3** | 개발자 (Developer) | **강제 동기화:** 변경된 브랜치를 원격에 강제로 푸시하며, 추적 관계를 재설정한다. | `git push -u origin master` (혹은 `main`) <br> *(만약 권한 오류가 발생하면, PAT 재발급 후 다시 시도한다.)* |
| **Step 4** | 개발자 (Developer) | **권한 재확인:** 모든 단계가 실패했을 경우, PAT 재발급 및 권한 검토를 진행한다. | GitHub 설정 페이지에서 `repo` 범위의 **쓰기 권한(Write Scope)**을 가진 새로운 토큰을 발급받고, 환경 변수를 업데이트한다. |

## ✅ 3단계: 검증 (Verify) - 성공 여부 확인

| 순서 (When) | 담당자 (Who) | 검증 목표 (What) | 검증 명령어 및 결과 확인 (How) |
| :---: | :--- | :--- | :--- |
| **Step 5** | 개발자 (Developer) | **최종 상태 확인:** 로컬과 원격이 완벽하게 동기화되었는지 확인한다. | 1. `git status`를 실행하여 "Your branch is up to date with 'origin/master'" 등의 메시지가 뜨는지 확인한다. <br> 2. **[최종 검증]** 성공적인 Push 로그를 확인한다. |
