## 💻 Part 1. 기술 스택 (Tech Stack) 제안

앱의 복잡성(AI 처리, 실시간 지도 연동, 대용량 데이터 처리)을 고려하여, 안정적이고 모듈화된 스택을 구성합니다.

| 영역 | 기술 스택 | 선택 이유 |
| :--- | :--- | :--- |
| **프론트엔드 (Client)** | **Flutter (Dart)** | iOS/Android 크로스 플랫폼 지원이 뛰어나 개발 속도가 빠르고, 커스터마이징이 자유로워 복잡한 UI/UX(와이어프레임 구현)를 높은 품질로 구현하기에 최적입니다. |
| **백엔드 (API/Logic)** | **Python (FastAPI)** | AI/ML 라이브러리(Pandas, NumPy, Scikit-learn)와의 연동이 가장 쉽고 빠릅니다. 비동기 처리(Async)가 용이하여 AI 로드맵 생성과 같은 장시간 작업을 처리하는 데 적합합니다. |
| **데이터베이스 (DB)** | **PostgreSQL + PostGIS** | **가장 중요합니다.** PostgreSQL은 안정적인 관계형 데이터베이스이며, **PostGIS 확장 기능**은 지리 공간 데이터(위도, 경도, 거리 계산) 처리에 있어 업계 최고 수준의 성능과 기능을 제공합니다. |
| **AI/ML 엔진** | **OpenAI/Gemini API** | 복잡한 자연어 처리(NLP)와 로드맵의 '의미론적 연결(Semantic Linking)'을 구현하는 데 필수적입니다. 사용자의 목적(Purpose)과 POI 간의 연관성을 추론합니다. |
| **인프라 (Cloud)** | **AWS (Amazon Web Services)** | 스케일 아웃(Scale-out)이 용이하며, Lambda (서버리스), S3 (스토리지), RDS (PostgreSQL 호스팅) 등 엔드투엔드 서비스를 제공하여 초기 개발 및 확장에 가장 안정적입니다. |

## 📐 Part 2. 데이터 아키텍처 및 파이프라인 설계

앱의 핵심은 단순한 데이터 저장이 아닌, **'목적(Purpose)'을 통해 데이터를 해석하고 재가공하는 파이프라인**입니다.

### 1. 데이터 수집 (Ingestion)
*   **출처:** 외부 API (Google Maps, Booking API 등), 웹 크롤링 (여행 블로그, 전문지), 사용자 입력.
*   **목표:** 원시(Raw) 형태의 데이터를 수집합니다. (예: "로마 콜로세움 근처 맛집 후기", "고대 로마 건축 역사 자료")

### 2. 데이터 처리 및 정제 (Processing & Cleaning)
*   **컴포넌트:** FastAPI Backend + AWS Lambda
*   **작업:**
    1.  **지리 정보 추출:** 모든 POI에 위도/경도를 표준화하여 추가합니다. (PostGIS 활용)
    2.  **데이터 정규화:** 다양한 출처의 리뷰/정보를 일관된 스키마로 변환합니다.
    3.  **핵심 엔티티 연결:** 수집된 정보가 어떤 `Purpose`와 연결될 수 있는지 잠재적 키워드를 추출합니다.

### 3. AI 기반 엔리치먼트 (AI Enrichment Layer) ⭐ 핵심
*   **컴포넌트:** OpenAI/Gemini API 호출 모듈
*   **작업:**
    1.  **의미론적 매핑:** 사용자가 입력한 `Purpose` (예: "르네상스 건축 학습")와 POI의 설명을 AI에 전달하여, 이 POI가 그 목적과 **얼마나 깊게 연관되어 있는지** 점수화합니다.
    2.  **로드맵 생성:** 이 점수화된 데이터를 기반으로, 시간적/지리적 제약 조건(예: 이동 시간, 개방 시간)을 만족하는 최적의 경로(Itinerary)를 생성합니다.
    3.  **결과 저장:** 최종적으로 최적화된 로드맵과 점수화된 관계 데이터를 `Itinerary` 테이블에 저장합니다.
