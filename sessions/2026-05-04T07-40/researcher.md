## 🛠️ GitHub 싱크 실패 자가 진단 체크리스트 (CEO 지시 기반)

GitHub 싱크 실패는 원인이 매우 다양하므로, 발생한 오류 메시지(Error Code)와 실패 시점을 기준으로 아래 목록을 순차적으로 점검하는 것이 가장 효율적입니다.

---

### 🔴 1. API Rate Limit 초과 (가장 흔한 원인)
특정 시간 동안 너무 많은 API 호출을 했을 때 발생합니다. 코드 자체의 오류가 아니라, **'사용 제한'**에 걸린 경우입니다.

| 구분 | 증상 및 에러 코드 | 자가 진단 질문 (Checklist) |
| :--- | :--- | :--- |
| **원인** | 403 Forbidden (Rate Limit Exceeded) | 1. 최근 1시간 이내에 대량의 자동화된 API 호출(스크립트, CI/CD 등)을 했는가? |
| | | 2. 현재 사용하고 있는 GitHub 토큰(Token)이 기본 사용자 토큰이 아닌, 높은 할당량의 토큰인가? |
| **해결 방향** | 호출 주기를 늘리거나, Organization/Enterprise 레벨의 유료 플랜으로 업그레이드 필요. |

### 🟡 2. 자격 증명(Credential) 오류
토큰 만료, 권한 부족, 계정 정보 불일치 등으로 인해 시스템이 접근을 거부할 때 발생합니다.

| 구분 | 증상 및 에러 코드 | 자가 진단 질문 (Checklist) |
| :--- | :--- | :--- |
| **원인** | 401 Unauthorized, Permission Denied | 1. 사용 중인 Personal Access Token (PAT)이 만료되지는 않았는가? (토큰 만료일 확인) |
| | | 2. 해당 토큰에 현재 작업에 필요한 모든 권한(Scope)이 부여되어 있는가? (예: `repo`, `workflow` 등) |
| | | 3. 로컬 환경의 Git Credential Manager에 저장된 비밀번호/토큰이 최신 정보와 일치하는가? |

### 🟢 3. 브랜치 충돌 (Branch Conflict)
여러 개발자가 동시에 같은 파일의 같은 라인을 수정했을 때, 병합(Merge) 과정에서 발생하는 논리적 충돌입니다.

| 구분 | 증상 및 에러 코드 | 자가 진단 질문 (Checklist) |
| :--- | :--- | :--- |
| **원인** | Merge Conflict, `CONFLICT` 마커 | 1. 현재 작업 브랜치가 메인(main) 또는 개발(develop) 브랜치와 차이가 발생하는 지점이 있는가? |
| | | 2. 푸시(Push)를 시도하기 전에 반드시 `git pull --rebase`를 통해 최신 원격 브랜치 내용을 받아왔는가? |
| **해결 방향** | 충돌이 발생한 파일을 열어, 어떤 코드가 최종 버전으로 남을지 수동으로 결정하고 병합해야 합니다. |

### 🔵 4. Webhook 설정 오류 (자동화/통합 문제)
GitHub 이벤트(Push, Pull Request 등)가 발생했을 때, 외부 시스템(CI/CD, Slack 등)으로 알림이나 작업을 트리거 하려다 실패할 때 발생합니다.

| 구분 | 증상 및 에러 코드 | 자가 진단 질문 (Checklist) |
| :--- | :--- | :--- |
| **원인** | 5xx Server Error (외부 시스템 오류), 로그 기록 없음 | 1. Webhook이 연결된 **외부 API 엔드포인트**가 현재 정상적으로 작동하고 있는가? |
| | | 2. Webhook Secret Key가 양쪽(GitHub와 수신 서버)에 정확하게 일치하는가? |
| | | 3. Webhook이 보내는 페이로드(Payload) 데이터 구조를 수신 서버가 정상적으로 파싱할 수 있는가? |

### 🟠 5. 로컬 환경 및 Git 명령어 오류
가장 기본적인 단계에서 발생할 수 있는 설정 또는 명령어 문제입니다.

| 구분 | 증상 및 에러 코드 | 자가 진단 질문 (Checklist) |
| :--- | :--- | :--- |
| **원인** | Generic Failure, 원격 주소 오류 | 1. `git remote -v` 명령어로 원격 저장소 URL이 정확하게 설정되어 있는가? |
| | | 2. 변경 사항을 커밋(`git commit`)하고 스테이징(`git add`)하는 과정을 빠뜨리지는 않았는가? |
| | | 3. 작업 디렉터리(Working Directory)에 트래킹되지 않는 대용량 파일이나 민감한 파일이 남아있지 않은가? |
